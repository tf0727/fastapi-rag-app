# 问题补全功能说明文档

## 📋 概述

问题补全功能是在多轮对话基础上新增的智能功能，能够根据对话历史自动补全用户输入中缺失的主谓宾成分，处理指代词和省略的情况。

## 🎯 功能目标

在多轮对话中，用户经常会使用：
- **指代词**：如"它"、"这个"、"那个"等
- **省略主语**：如"价格多少？"、"配置呢？"等
- **简短追问**：如"颜色？"、"还有呢？"等

问题补全功能会自动将这些不完整的问题补全为完整的、语义明确的问题，提高检索和回答的准确性。

## 🔧 技术实现

### 1. 新增组件

#### 工具函数：`query_completion_tool`

```python
@tool
def query_completion_tool(current_question: str, history: str) -> str:
    """根据对话历史补全当前问题的主谓宾，处理指代词和省略的情况"""
```

**功能**：
- 接收当前问题和对话历史
- 使用 LLM 分析并补全问题
- 返回补全后的完整问题

**输入参数**：
- `current_question`：用户当前输入的问题
- `history`：格式化的对话历史字符串

#### 节点函数：`query_completion_node`

```python
def query_completion_node(state: MessagesState):
    """根据对话历史补全当前问题的主谓宾"""
```

**功能**：
- 从 state 中提取当前问题和历史对话
- 调用 `query_completion_tool` 进行补全
- 返回补全后的问题（作为 ToolMessage）

### 2. 工作流修改

#### 新的工作流程

```
START 
  ↓
relevance_check (相关性判断)
  ↓
  ├─ 相关 → query_completion (问题补全) ← 新增节点
  │           ↓
  │         rewrite (问题改写)
  │           ↓
  │         query_router (路由)
  │           ↓
  │         [retriever] (检索)
  │           ↓
  │         generate_answer_with_retriever (生成答案)
  │           ↓
  │         END
  │
  └─ 不相关 → generate_answer (直接生成答案) → END
```

#### 边的连接变化

**之前**：
```python
relevance_check → rewrite → query_router → ...
```

**现在**：
```python
relevance_check → query_completion → rewrite → query_router → ...
```

### 3. 改写节点优化

`rewrite_node` 现在优先使用补全后的问题：

```python
def rewrite_node(state: MessagesState):
    # 优先使用补全后的问题
    for msg in reversed(state["messages"]):
        if msg.tool_call_id == "query_completion_tool":
            completed_question = msg.content
            break
    
    # 如果没有补全，使用原始问题
    if not completed_question:
        # 获取原始用户问题
        ...
```

## 📊 补全策略

### 历史上下文提取

- **提取范围**：最近 3 轮对话
- **内容截断**：每条 AI 回复截取前 200 字符
- **格式化**：
  ```
  - 用户：[问题1]
  - AI：[回答1]...
  
  - 用户：[问题2]
  - AI：[回答2]...
  ```

### 补全规则

1. **有指代词**：替换为具体实体
   - "它" → 从历史中提取具体产品/主题
   - "这个"、"那个" → 从历史中提取具体对象

2. **省略主语**：补全主语
   - "价格多少？" → "[产品名]的价格多少？"
   - "配置呢？" → "[产品名]的配置是什么？"

3. **简短追问**：补全主谓宾
   - "颜色？" → "[产品名]有哪些颜色？"
   - "效果如何？" → "[主题]的效果如何？"

4. **已完整问题**：直接返回原问题
   - "小米SU7多少钱？" → "小米SU7多少钱？"

## 🎯 优势与价值

### 1. 提高检索准确性

**问题**：用户使用"它"、"这个"等指代词
**影响**：检索系统无法理解"它"指什么，导致检索失败
**解决**：补全后的完整问题包含具体实体，检索更准确

### 2. 改善用户体验

**问题**：用户需要重复输入完整问题
**影响**：对话不自然，用户体验差
**解决**：用户可以自然追问，系统自动理解

### 3. 提升回答质量

**问题**：不完整的问题导致回答不准确
**影响**：AI 可能无法理解用户真实意图
**解决**：完整的问题帮助 AI 生成更准确的回答

## 🐛 常见问题

### Q1: 补全结果不准确怎么办？

**原因**：
- 历史上下文不足
- Prompt 设计不够好
- LLM 理解有偏差

**解决**：
1. 增加历史长度：`recent_pairs = min(5, ...)`
2. 优化补全提示词，添加更多样例
3. 使用更强大的 LLM 模型

### Q2: 补全速度慢怎么办？

**原因**：需要额外调用一次 LLM

**解决**：
1. 使用更快的 LLM 模型（如 gpt-3.5-turbo）
2. 减少历史上下文长度
3. 考虑使用缓存机制

### Q3: 首轮对话也会补全吗？

**回答**：是的，但首轮通常已经是完整问题，补全后会直接返回原问题。

### Q4: 如何关闭补全功能？

**回答**：需要修改工作流，将 `query_completion` 节点移除，恢复原来的边连接：

```python
# 将这行
workflow.add_conditional_edges(..., {False: "query_completion", ...})
# 改为
workflow.add_conditional_edges(..., {False: "rewrite", ...})

# 并移除这行
workflow.add_edge("query_completion", "rewrite")
```

## 📈 性能影响

### 额外开销

- **LLM 调用**：每轮对话增加 1 次 LLM 调用
- **Token 消耗**：约 200-500 tokens（取决于历史长度）
- **时间延迟**：约 0.5-1.5 秒（取决于 LLM 速度）

### 优化建议

1. **使用快速模型**：补全使用较快的模型（如 gpt-3.5-turbo）
2. **减少历史**：只传递必要的历史信息
3. **并行处理**：考虑与其他步骤并行执行（需要修改工作流）

## 🔄 与其他功能的协同

### 与问题改写的协同

```
用户输入："它有哪些颜色？"
    ↓
问题补全："小米15有哪些颜色？"
    ↓
问题改写："小米15的颜色选项"
    ↓
检索和回答
```

补全和改写是两个独立的步骤：
- **补全**：处理指代词和省略，生成完整问题
- **改写**：将疑问句改为陈述句，便于检索

### 与路由的协同

补全后的完整问题使路由更准确：

```
不完整问题："价格多少？" → 路由可能失败
完整问题："小米15的价格多少？" → 准确路由到产品查询
```

### 与检索的协同

完整的问题包含关键实体，检索更准确：

```
检索"它有哪些颜色"：可能检索不到相关内容
检索"小米15有哪些颜色"：准确检索到小米15的颜色信息
```
