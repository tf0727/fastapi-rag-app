## 数据流详解

### 场景1：产品信息查询

```
用户输入: "小米14 Pro的处理器是什么？"
    ↓
[START]
    ↓
[relevance_check] 
    → LLM判断: "与小米相关"
    → 输出: "是"
    ↓
[rewrite]
    → LLM改写
    → 输入: "小米14 Pro的处理器是什么？"
    → 输出: "小米14 Pro的处理器型号和配置"
    ↓
[query_router]
    → LLM分类
    → 输入: "小米14 Pro的处理器型号和配置"
    → 分析: 关键词"处理器"、"配置" → 产品参数
    → 输出: "产品"
    ↓
[route_query] (条件边判断)
    → 判断: "产品" in route_result
    → 路由到: "retriever_elasticsearch"
    ↓
[retriever_elasticsearch]
    → 调用: elasticsearch_retriever_tool
    → 查询向量: embedding("小米14 Pro的处理器型号和配置")
    → 检索字段:
        • 商品名称_embedding (权重: 2.5)
        • 简介_embedding (权重: 2.0)
        • 类别_embedding (权重: 1.0)
        • 详细参数_embedding (权重: 1.5)
    → 返回结果:
        产品：小米14 Pro
        类别：手机
        简介：...
        价格：4999元起
        详细参数：处理器: 骁龙8 Gen 3...
        相关度评分：8.52
    ↓
[generate_answer_with_retriever]
    → 构建提示词:
        用户问题: "小米14 Pro的处理器是什么？"
        上下文: [检索结果]
    → LLM生成答案:
        "根据产品信息，小米14 Pro搭载了骁龙8 Gen 3处理器..."
    ↓
[END]
```

### 场景2：公司信息查询

```
用户输入: "小米集团在2024年的碳排放目标是什么？"
    ↓
[START]
    ↓
[relevance_check]
    → LLM判断: "与小米相关"
    → 输出: "是"
    ↓
[rewrite]
    → LLM改写
    → 输入: "小米集团在2024年的碳排放目标是什么？"
    → 输出: "小米集团2024年碳排放目标"
    ↓
[query_router]
    → LLM分类
    → 输入: "小米集团2024年碳排放目标"
    → 分析: 关键词"碳排放"、"目标" → ESG/环境政策
    → 输出: "公司"
    ↓
[route_query] (条件边判断)
    → 判断: "产品" not in route_result
    → 路由到: "retriever_faiss"
    ↓
[retriever_faiss]
    → 调用: faiss_retriever_tool
    → 查询向量: embedding("小米集团2024年碳排放目标")
    → 检索方式: 余弦相似度
    → Top-K: 5
    → 返回结果:
        [Document 1]
        内容: "小米集团承诺在2024年实现碳达峰..."
        来源: 2024年ESG报告
        
        [Document 2]
        内容: "我们的碳排放目标包括..."
        来源: 环境政策文件
    ↓
[generate_answer_with_retriever]
    → 构建提示词:
        用户问题: "小米集团在2024年的碳排放目标是什么？"
        上下文: [检索结果]
    → LLM生成答案:
        "根据小米集团2024年ESG报告，小米集团在2024年的碳排放目标是..."
    ↓
[END]
```

## 消息流结构

### 产品查询的消息序列
```python
[
    HumanMessage(content="小米14 Pro的处理器是什么？"),          # [0]
    ToolMessage(content="是", tool_call_id="relevance_check"),  # [1]
    ToolMessage(content="小米14 Pro的处理器型号", tool_call_id="rewrite"),  # [2]
    ToolMessage(content="产品", tool_call_id="query_router"),   # [3]
    ToolMessage(content="产品：小米14 Pro...", tool_call_id="elasticsearch"),  # [4]
    AIMessage(content="小米14 Pro搭载了...")                     # [5]
]
```

### 索引说明
- `state["messages"][0]` - 原始用户问题
- `state["messages"][-1]` - 最新消息（在不同节点意义不同）
- `state["messages"][-2]` - 倒数第二条消息（在检索节点中是改写后的问题）

## 性能优化建议

1. **缓存层**: 添加 Redis 缓存常见查询
2. **并行检索**: 对于模糊查询，可并行检索两个数据库
3. **结果重排**: 使用重排模型优化检索结果
4. **流式输出**: 使用 LLM 流式输出提升用户体验
5. **批量处理**: 支持批量查询处理

## 监控指标

1. **路由准确率**: 查询路由到正确数据库的比例
2. **检索召回率**: 检索结果包含答案的比例
3. **答案质量**: 用户满意度评分
4. **响应时间**: 从查询到答案的总时间
5. **数据库命中率**: 各数据库的使用频率
